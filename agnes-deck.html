Project Agnes

High-stakes bets, made on fragmented evidence.

A living evidence graph. Rewind to what was knowable at any moment, see what the strategy depends on, and how new evidence changes it.

Agnes does three things
Validatewhat has to be true — and whether anyone has actually checked
Simulaterun the alternatives in parallel — change the variables and see which version the evidence supports
Monitorre-score all of them every time something new is published
One  ·  Validate

What has to be true for this to work?

Strategy decks list goals, not the conditions underneath them.
If nobody writes down what must be true, nobody notices when it stops being true.

Two  ·  Simulate

Three ways to run the same business.

All three need the same six things to be true. What changes is how badly each one hurts you.

Zillow chose the first. Same evidence, same six questions, same day.

Three  ·  Monitor

Has anything changed enough to act?

The evidence that kills a bet arrives slowly, inside ordinary quarterly filings.
Nobody re-reads the original reasoning each time a new one lands.

What we built
A decision graphin Neo4j — the bet, the six things that had to be true, and every piece of evidence for or against each one
18 dated factsfrom Zillow's own filings and from the world around it — a competitor's results, national price data, Federal Reserve reports
One hard ruleevery fact carries the date it became public, and Agnes only ever sees what was published on or before the date you pick

Biggest feedback

Two things cost us time.

Free vs trialthe workshop said “create an Aura Free database”; the signup flow ran a five-step wizard and started a 14-day trial instead. We could not tell if we were on the right thing.
Silent successpasting a long seed script runs every statement and shows a tick for each — but hides the final result. It read as a failure when everything had worked.
